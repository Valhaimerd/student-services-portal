# Report and Submission Checklist

## Evidence to collect while working

- development-tool versions;
- terminal output or screenshots for execution, type checking, linting, and formatting;
- GitHub repository URL;
- Issue, branch, commits, Pull Request, and review evidence;
- AI prompt and response;
- verification source from official documentation; and
- an explanation of an AI suggestion that was accepted, modified, or rejected.

Do not postpone evidence collection until the end.

## AI review record

```text
AI Tool:

Prompt Used:

AI Recommendation:

What I Understood:

Recommendation Accepted:

Recommendation Modified:

Recommendation Rejected:

Reason:

Claim or Code Verified:

Official Source:

Verification Result:
```

## Required deliverables

- GitHub repository URL and environment screenshot;
- `README.md`, `.gitignore`, `package.json`, TypeScript configuration, ESLint configuration, and Prettier configuration;
- TypeScript source and runtime-validation example;
- GitHub Issue, feature branch, meaningful commits, Pull Request, and code-review evidence;
- AI prompt/response, completed AI review record, verification source, and accepted/modified/rejected explanation; and
- short reflection.

## Reflection

Answer each question in three to five sentences:

1. What changed compared with your previous programming workflow?
2. Why was the feature branch useful?
3. Which AI suggestion required modification, and why?
4. How did TypeScript prevent or reveal a problem?
5. Why was runtime validation still needed?
6. What information must never be committed?
7. Which step in **Ask → Understand → Review → Modify → Test → Verify → Commit** mattered most, and why?
8. How would this workflow help a development team?

## Final quality check

Before submission, confirm that the project demonstrates strong typing, generics, narrowing from `unknown`, runtime validation, working quality tools, clean Git history, a complete GitHub collaboration flow, responsible AI use, and concise documentation.
